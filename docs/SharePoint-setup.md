# SharePoint 설치판 5.2 사용 안내

이 설치판은 **회사 SharePoint 페이지 안에서 현재 로그인한 회사 계정**으로 관리 엑셀을 읽고 저장합니다. 직원이 Client ID·Tenant ID를 입력하지 않습니다. 별도의 Microsoft Entra 앱 등록이나 Microsoft Graph 권한 요청을 추가하지 않습니다.

담당자가 사이트에 한 번 설치하고 엑셀을 지정하면, 직원은 게시된 SharePoint 페이지에서 **사진 촬영·앨범 선택 → 자동 인식 → 같은 엑셀에 저장** 순서로 사용합니다. 실제 파일 접근과 저장 결과를 확인한 뒤 완료로 표시합니다.

## 담당자: 처음 한 번, 네 단계

1. PC에서 [SharePoint 설치 파일 받기](https://github.com/geonwook-kang/Tool-management-/raw/refs/heads/tool-manager-download/downloads/Tool-Manager-SharePoint-5.2.sppkg)를 눌러 `.sppkg` 파일을 저장합니다. [설치 안내·소스 ZIP](https://github.com/geonwook-kang/Tool-management-/raw/refs/heads/tool-manager-download/downloads/Tool-Manager-SharePoint-5.2.zip)도 제공합니다. 휴대폰에 직접 설치하는 APK 파일은 아닙니다.
2. 회사에서 사용하는 **앱 카탈로그 → SharePoint용 앱(Apps for SharePoint)**에 `.sppkg`를 업로드하고, 표시되는 **사용(Enable app)·배포(Deploy)** 절차를 진행합니다. 사이트용 앱 카탈로그가 있으면 그 카탈로그를 사용하고, 조직용 카탈로그로 설치할 수도 있습니다. **관리 엑셀을 올리는 일반 문서(Documents) 폴더에 올리는 것으로는 프로그램이 설치되지 않습니다.**
3. 사용할 팀 사이트의 **사이트 콘텐츠 → 새로 만들기 → 앱**에서 `Tool Manager SharePoint`를 추가합니다. 사이트의 **새 페이지**를 만들거나 기존 페이지를 편집하고, 본문의 **＋**에서 **툴 검교정 매니저** 웹 파트를 추가합니다.
4. 웹 파트의 **연필(편집)** 버튼을 누릅니다. **관리 엑셀 → SharePoint 엑셀 링크 또는 사이트 안의 파일 경로**에 이 사이트의 관리 엑셀 링크를 한 번 붙여 넣고 적용합니다. 연결된 파일 이름을 확인하고 **게시(Publish)**한 뒤, **이 SharePoint 페이지의 링크**를 직원들에게 전달합니다.

앱 카탈로그의 위치와 설치 메뉴는 회사 사이트 구성에 따라 다릅니다. 문서 편집 권한과 사이트 앱 설치 권한은 별개이므로 모든 직원에게 위 메뉴가 보인다고 단정하지 않습니다. 메뉴가 없거나 실제 설치 오류가 표시되면, 그 화면과 오류 문구를 기준으로 다음 단계를 확인합니다. 사전에 모든 회사에서 관리자 승인이 필요하다고 판단하는 절차는 없습니다.

사이트에 이미 추가한 뒤에는 페이지 편집에서 엑셀 링크를 변경할 수 있습니다. 새 파일은 같은 사이트 안의 `.xlsx`여야 합니다. 경로가 포함된 Excel 공유 링크(`/:x:/r/…`)도 사용할 수 있으며, 요청은 현재 SharePoint 사이트로만 보냅니다. 공유 링크의 임시 쿼리 값은 연결 정보나 패키지에 저장하지 않습니다.

## 직원: 휴대폰에서 사진만 올리기

1. 담당자가 보낸 **게시된 SharePoint 페이지 링크**를 Android의 Chrome 또는 iPhone의 Safari에서 엽니다. 회사 로그인 화면이 나오면 평소 회사 계정으로 로그인합니다.
2. **공유 엑셀 연결됨**과 대상 파일 이름을 확인합니다.
3. **사진 촬영** 또는 **앨범에서 선택**으로 툴 라벨·SMAX 화면을 올립니다. **회사 공유 원본에 저장하고 내용을 확인했습니다**라는 결과까지 확인합니다.

직원에게 앱 ID·테넌트 ID·관리 엑셀 경로를 묻지 않습니다. SharePoint 페이지는 휴대폰 홈 화면의 바로가기로 추가할 수도 있습니다. 사진은 기기에서 인식하며, 회사 엑셀 읽기·저장에는 인터넷이 필요합니다. 기존 회사 앱에 로그인돼 있더라도 현재 브라우저에서 SharePoint 페이지 로그인이 추가로 표시될 수 있습니다.

## 어느 링크를 공유하나요?

| 주소 | 용도 |
|---|---|
| 설치 후 게시한 회사 SharePoint 페이지 | 직원의 촬영·업로드·공유 원본 자동 저장 |
| 관리 엑셀의 공유 링크 | 담당자가 웹 파트 설정에 한 번 입력하는 대상 파일 |
| 공개 GitHub Pages 앱 주소 | 설치판 받기, 설치 안내, PC·기기 사본·고급 외부 앱 연결 |

공개 GitHub Pages 앱은 회사 SharePoint와 다른 사이트에서 실행됩니다. 그 공개 주소만으로 회사 브라우저의 SharePoint 로그인 권한을 가져와 쓰지는 않습니다. **별도 앱 ID 없이 사용하는 설치판은 회사 SharePoint 페이지에서 열어야 합니다.** 기존 Microsoft 365 외부 연결 방식은 고급 설정으로 유지하며 [별도 안내](Microsoft365-setup.md)를 참고할 수 있습니다.

## 날짜와 사진 저장

- 툴 라벨의 **교정일자 → Cal Last**, **차기교정예정일자 → Cal Next**에 저장하고, 사진은 **Label Photo**에 넣습니다.
- SMAX의 **Serial/Asset Number**로 툴을 연결하고 사진은 **SMAX Tool Photo**에 넣습니다. 확인된 **Calibration Due Date → Cal Next**를 반영하며, 작성·수정 일시로 Cal Last를 바꾸지 않습니다.
- 기존 셀·서식·다른 사진을 보존합니다. 저장 전 원본 백업을 기기에 보관합니다. 체크아웃으로 파일을 잠시 확보한 뒤 원본 내용이 같은지 확인하고 저장하며, 체크인과 저장 후 내용 확인까지 완료해야 성공으로 표시합니다. 기존 체크아웃이나 다른 사용자의 초안을 해제하지 않습니다.
- 인식 결과가 불확실한 사진이나 변경 충돌은 자동 저장 완료로 표시하지 않습니다. 실제로 읽히지 않은 이름·시리얼·날짜를 만들어 넣지 않습니다.

## 실제 오류가 나왔을 때

| 표시된 결과 | 다음 조치 |
|---|---|
| 401 또는 회사 로그인 필요 | 같은 SharePoint 페이지를 다시 열어 회사 로그인을 완료합니다. |
| 403 또는 현재 계정으로 파일을 수정할 수 없음 | 해당 계정으로 대상 엑셀을 열어 편집 가능한지 확인합니다. |
| 404 또는 엑셀을 찾을 수 없음 | 페이지 편집에서 같은 사이트의 `.xlsx` 링크와 파일 위치를 확인합니다. |
| 412 또는 다른 사용자가 파일을 변경함 | 원본을 덮어쓰지 않습니다. 최신 파일을 다시 읽고 처리합니다. |
| 409·423 또는 파일 잠김 | Excel의 다른 저장 작업이 끝난 뒤 최신 원본으로 다시 시도합니다. |
| 저장 완료 여부를 확인할 수 없음·체크아웃이 남음 | 자동 재전송하지 않습니다. 원본과 기기에 보관한 저장 전 백업을 확인하고, SharePoint에서 본인이 방금 저장한 파일의 체크인 상태를 확인합니다. 다른 사람의 체크아웃은 해제하지 않습니다. |
| 앱 시작 응답을 받지 못함·스크립트 실행 오류 | 페이지를 다시 열고 실제 오류 문구를 확인합니다. 사이트의 콘텐츠 보안 정책(CSP)으로 앱 스크립트·인식 엔진 실행이 제한되는지도 확인합니다. |
| 앱 카탈로그·앱 추가 메뉴가 보이지 않음 | 현재 사이트의 설치 메뉴와 표시된 안내를 확인합니다. 일반 문서 업로드 메뉴와 구분합니다. |

## 검증 범위

브라우저 자동 검사는 같은 사이트 안의 앱 화면, 회사 로그인 세션을 사용하는 요청, 실제 사진 OCR, 날짜·사진 OOXML 반영, 백업과 파일 버전 충돌을 확인합니다. SharePoint 서버 응답은 통제된 테스트이며, 실제 회사 테넌트 설치·다른 엔지니어의 계정·물리 휴대폰에서의 실행은 사용 환경에서 확인해야 합니다. 패키지에는 회사 공유 URL·실제 엑셀·사진·로그인 쿠키·토큰을 넣지 않습니다.
